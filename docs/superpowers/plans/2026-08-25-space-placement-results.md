# 다른 Space에 창 배치 — 검증 결과

측정일: 2026-08-25

결론부터: **공개 API로도 비공개 API로도 안 된다.** SIP를 부분 해제하지 않으면 다른 앱의
창을 다른 Space로 옮길 수 없다.

## 무엇을 재봤나

macOS는 Space를 다루는 공개 API를 주지 않는다. 대신 창 서버(SkyLight, 옛 CoreGraphics)의
비공개 함수가 있고 yabai 같은 도구가 그것을 쓴다. 헤더가 없으므로 `@_silgen_name`으로
직접 선언해 불러봤다.

### 읽기는 된다

```
CGSMainConnectionID()          -> 1238811
CGSCopyManagedDisplaySpaces()  -> 디스플레이별 Space 목록
CGSCopySpacesForWindows()      -> 창이 어느 Space에 있는지
```

이 컴퓨터에서 나온 결과다.

```
디스플레이 37D8832A...: Space 3개, 현재=1849
   id=1     데스크탑
   id=1849  전체화면
   id=1960  전체화면
디스플레이 914EBD59...: Space 2개, 현재=2415
   id=2364  데스크탑
   id=2415  전체화면
```

### 옮기기는 안 된다

`CGSMoveWindowsToManagedSpace`를 Safari 창에 두 가지로 시도했다.

| 시도 | 결과 |
|---|---|
| 다른 디스플레이의 데스크탑(1 -> 2364) | 실패. Space가 그대로 [1] |
| 같은 디스플레이의 다른 Space(1 -> 1849) | 실패. Space가 그대로 [1] |

오류를 던지지 않고 조용히 아무 일도 하지 않는다. 자기 앱의 창이 아니면 창 서버가 요청을
무시한다. yabai가 이 기능을 쓰려고 SIP 부분 해제를 요구하는 이유가 여기 있다.

## 그래서 어떻게 하고 있나

Mission Control 설정으로 우회한다.

> 시스템 설정 > 데스크탑 및 Dock >
> "응용 프로그램으로 전환할 때, 해당 앱의 열린 윈도우가 있는 공간으로 전환"

이것을 켜면 `AXFrontmost`로 앱을 활성화할 때 macOS가 그 앱의 Space로 넘어간다. 넘어간
뒤에는 AX가 창을 보므로 배치할 수 있다. 측정값이다.

```
활성화 전 AX 창 0개  ->  AXFrontmost 설정  ->  활성화 후 2개
```

전체화면으로 다른 Space에 있던 Safari를 `restage open`이 `placed`로 배치하는 것까지
확인했다.

차이는 이렇다.

| | 창을 옮긴다 | 그 Space로 넘어간다 |
|---|---|---|
| 필요한 것 | SIP 부분 해제 | 설정 하나 |
| 화면 | 그대로 | 데스크탑이 전환된다 |
| 위험 | 비공개 API, OS 업데이트마다 깨질 수 있음 | 없음 |

## 하지 않기로 한 것

비공개 API를 쓰지 않는다. 세 가지 이유다.

- **동작하지 않는다.** 위 측정대로 SIP 해제 없이는 무시된다
- SIP 부분 해제는 사용자의 보안 결정이지 도구가 요구할 것이 아니다
- 헤더 없는 비공개 함수는 OS 업데이트마다 깨질 수 있고, 깨져도 조용히 실패한다

읽기 전용 함수(`CGSCopySpacesForWindows`)는 창이 어느 Space에 있는지 정확히 알려주므로
쓸모가 있지만, 지금은 `CGWindowList`의 화면 표시 여부로 같은 판정을 하고 있어 굳이
비공개 API를 들일 이유가 없다.
