# 설치된 앱 동적 검색과 restage new — 검증 결과

측정일: 2026-08-24

1단계 설계에서 정한 `AppRegistry`를 없애고 `InstalledApps`로 대체했다. 그 문서를 읽을 때는 이 문서를 함께 봐야 한다.

## 왜 고정 목록을 버렸나

1단계에서 `AppRegistry`에 논리 이름 10개를 매핑으로 두었다. 그때는 검증 표본을 고정해야 했으므로 맞는 선택이었다.

오픈소스로 공개하면서 전제가 깨졌다. 그 10개는 이 저장소를 만든 컴퓨터의 앱 목록이다. 받는 사람의 컴퓨터에는 다른 앱이 깔려 있고, 목록에 없는 앱을 쓰려면 소스를 고치고 다시 빌드해야 했다.

`probeSample`과 `protected`도 같은 문제였다. `protected`에 `cursor`와 `chrome`을 박아둔 것은 이 컴퓨터에서 개발 세션과 브라우저를 지키기 위한 것이지, 남의 컴퓨터에서는 아무 의미가 없다.

`bundle ID는 한 파일에만 존재한다`는 규칙은 그대로다. 그 파일이 `AppRegistry.swift`에서 `InstalledApps.swift`로 옮겨졌을 뿐이다.

## 측정

### 표준 위치 109개, Spotlight 전체 388개

`/Applications`, `/System/Applications`, `~/Applications`와 각 Utilities, `/System/Library/CoreServices`를 훑으면 109개가 나온다. Spotlight로 `com.apple.application-bundle`을 전부 찾으면 388개다.

차이 279개는 다른 앱 안에 들어 있는 도우미 앱, 개발 도구가 품은 내부 앱, 내려받기 폴더에 남은 것들이다. 사용자가 이름으로 부를 대상이 아니므로 표준 위치만 쓴다.

표시 이름이 겹치는 앱은 하나도 없었다. 파일 이름과 표시 이름이 다른 경우는 있다. `FindMy.app`의 표시 이름은 `Find My`다. 그래서 둘 다로 찾을 수 있게 했다.

### 이름 대응은 단계를 나눠야 한다

한 가지 규칙으로는 안 된다.

| 입력 | 기대 | 단순 부분일치의 문제 |
|---|---|---|
| `chrome` | Google Chrome | 정확 일치가 없어 부분일치가 필요하다 |
| `Claude` | Claude | `Claude Code Notifier`로 샌다 |
| `microsoft` | 실패 | Edge와 Word 둘에 걸린다 |

그래서 정확히 일치 → 정규화(영숫자만) 일치 → 단어 일치 순으로 좁히고, 여럿에 걸리면 후보를 알려주고 멈춘다. 이 판정은 파일 시스템을 건드리지 않는 순수 함수라 고정 목록으로 검증한다. 검증 결과가 검증하는 사람의 컴퓨터에 좌우되면 안 된다.

### 브라우저 판정에는 확실한 신호가 없다

두 가지를 재봤다.

| 앱 | https 열기 등록 | html 뷰어 등록 | 실제 브라우저 |
|---|---|---|---|
| Google Chrome | 예 | 예 | 예 |
| Safari | 예 | **아니오** | 예 |
| Chromium | 예 | 아니오 | 예 |
| iTerm | **예** | **예** | 아니오 |
| ChatGPT | **예** | 아니오 | 아니오 |
| Notion | 아니오 | 아니오 | 아니오 |

`CFBundleDocumentTypes`의 html 뷰어 여부는 Safari가 빠지고 iTerm이 들어와 더 나빴다.

https 등록 여부를 느슨한 필요조건으로만 쓴다. Notion이나 카카오톡처럼 명백히 아닌 앱은 걸러지고, iTerm과 ChatGPT는 통과하지만 실제 탭 조회에서 실패한다. 최종 판정은 시도 결과에 맡긴다.

## 브라우저를 목록이 아니라 두 갈래로

Safari만 독자 어휘를 쓰고 나머지는 Chromium 문법이 같다. 그래서 브라우저를 하나씩 등록하지 않고 Safari만 예외로 둔다. Edge, Brave, Arc, Whale, Vivaldi가 코드 수정 없이 같은 경로를 탄다.

**실제로 검증한 것은 Safari와 Chrome 둘뿐이다.** 나머지는 이 컴퓨터에 설치되어 있지 않아 확인할 수 없었다. 설계상 같은 경로지만 그것은 검증이 아니다.

Firefox 계열은 탭 제어 어휘를 외부에 열어두지 않는다. 되는 척하지 않고 명확히 실패로 보고한다.

## restage new

### 캡처를 넣기로 한 결정

전체 스펙은 "캡처 기능 없음, 사용자가 전부 선언한다"였다. 이 사이클에서 뒤집었다.

원칙의 목적은 좌표를 저장하지 않는 것이었다고 보고, 좌표 대신 slot으로 분류해 저장하므로 목적은 지킨다. `SlotClassifier`가 창과 각 slot 영역의 교집합을 합집합으로 나눈 값으로 가장 가까운 것을 고른다.

교집합 비율만 쓰면 안 된다. 화면을 가득 채운 창이 모든 slot에서 만점을 받는다. 합집합으로 나누면 모자란 경우와 넘치는 경우가 함께 벌점을 받는다.

0.9 아래면 물음표를 붙여 되묻는다. 조용히 추측한 값을 저장하면 사용자가 의도하지 않은 config가 만들어진다.

### 창 짝짓기는 제목으로 안 된다

AX가 본 창과 브라우저가 아는 창을 맞춰야 하는데 공통된 id가 없다. 처음에는 제목으로 맞추려 했고 실패했다. 원인을 측정했다.

```
AppleScript(name of w):  (15) 배그 파트너 특혜 자기장 - YouTube 🔊
AX(AXTitle):             (15) 배그 파트너 특혜 자기장 - YouTube - Chrome
```

Chrome은 소리가 나면 확성기 기호를 붙이고, AX 제목에는 앱 이름을 덧붙인다. 한쪽이 다른 쪽의 접두사도 아니라 접두사 매칭으로도 안 된다.

Safari에서는 창 세 개의 제목이 전부 `Example Domain`으로 겹쳤다.

열거 순서도 다르다.

```
AppleScript:  시작 페이지, Example Domain, Example Domain
AX:           Example Domain, Example Domain, 시작 페이지
```

AX는 최근 활성 순인데 AppleScript는 그렇지 않다. 순서로도 안 된다.

반면 `bounds`는 AX의 위치·크기와 정확히 같은 값을 준다.

```
AppleScript bounds:  0,33,864,1059
AX position/size:    0,33  864x1026
```

`bounds`는 좌·상·우·하이므로 폭과 높이로 바꾸면 정확히 일치한다. 그래서 좌표로 맞춘다. 창이 완전히 겹쳐 있으면 여럿이 걸리지만 그때는 어느 것을 골라도 결과가 같다.

### 브라우저 내부 페이지는 담지 않는다

Safari 시작 페이지는 `favorites://`, Chrome 새 탭은 `chrome://newtab/`으로 나온다. 그대로 config에 적으면 나중에 `restage open`이 열 수 없는 주소를 열려고 한다. http와 https만 담는다.

스킴이 없으면 담는다. 사용자가 `example.com`이라고 적는 경로를 막지 않기 위해서다.

### GUI 대신 터미널

메뉴바에 폼 창을 띄우는 안도 있었다. 터미널을 고른 이유는 GUI를 자동으로 검증할 수 없기 때문이다. 6단계 메뉴바에서 겪었다. 입력을 파이프로 흘려넣고 결과 파일을 검사할 수 있어야 "된다"고 말할 근거가 생긴다.

이 흐름은 어차피 몇 줄 보고 Enter가 끝이라 GUI 이점이 크지 않다. 필요해지면 생성 로직을 그대로 재사용할 수 있다.

## probe의 강제 종료를 옵트인으로

기존에는 콜드 스타트가 기본이었고 `protected` 목록으로 두 앱만 지켰다. 이제 `--cold`를 줄 때만 종료하고, `--app`으로 하나만 지정해야 하며, 실행 전에 확인을 받는다.

보호 목록을 코드에 두는 대신 파괴적 동작 자체를 기본에서 뺐다.

## 검증

단위 테스트 125개 통과, 빌드 경고 없음.

순수 로직은 고정 입력으로 검증했다. slot 분류, YAML 왕복, 이름 대응, 창 좌표 대응, AppleScript 출력 파싱, 담을 주소 가리기.

끝단은 직접 돌렸다.

1. 실제 창 배치를 캡처해 config 생성
2. `restage open`으로 재현 확인
3. 한 번 더 실행해 세 항목 모두 `alreadySatisfied` — 아무것도 움직이지 않음

## 남은 것

- Chrome 외 Chromium 브라우저 검증. 설치된 것이 없어 못 했다
- 문서 표의 앱 이름 열 너비를 내용에 맞췄다. 이름이 고정 목록이 아니게 되면서 `Google Chrome`처럼 긴 이름에 표가 깨졌기 때문이다
