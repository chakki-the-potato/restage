# 4단계 검증 결과 — 브라우저 탭 제어

측정일: 2026-08-23
검증 브라우저: Safari만. Chrome은 사용자가 작업 중이며 유튜브가 열려 있어 대상에서 제외했다.
Rectangle 종료, `caffeinate`로 화면 잠금 차단

## 결과

### 탭 열기와 창 배치

`examples/research.yaml` — `window: separate`, `slot: right-half`, 탭 2개.

```
web  safari  placed  864,33 864x1027  864,33 864x1027  탭 1개 추가.
```

전용 창이 우측 절반에 배치되고 탭이 열린다. 사용자의 기존 Safari 창(시작 페이지)은 그대로 남는다.

### 멱등성

```
web  safari  alreadySatisfied  864,33 864x1027  -  탭 2개와 창 위치 모두 이미 목표 상태
```

반복 실행해도 창이 늘지 않고 탭도 중복되지 않는다.

### 사용자 탭 보존

전용 창에 `https://example.net`을 수동으로 추가한 뒤 재실행했다.

```
탭: https://example.com/  https://example.org/  https://example.net/
```

수동 추가한 탭이 그대로 남았다. 비파괴 원칙이 실제로 지켜진다.

### 증분 추가

config에 `https://example.edu/`를 추가하고 실행했다.

```
web  safari  placed  ...  탭 1개 추가.
탭: https://example.com/  https://example.org/  https://example.net/  https://example.edu/
```

새 URL만 열리고 기존 탭은 유지된다.

### 지원하지 않는 브라우저

```
web  notion  skipped  지원하지 않는 브라우저입니다. 지원: safari, chrome
```

## 검증 중 발견해 수정한 것

### 1. `tell` 블록 안에서 `tab`이 브라우저 클래스로 해석된다

가장 중요한 발견이다. 창 목록을 읽는 스크립트가 필드 구분자로 AppleScript의 `tab` 상수를 썼는데, `tell application "Safari"` 블록 안에서는 그것이 Safari의 `tab` 클래스로 해석된다.

실제 출력을 바이트로 확인해서 잡았다.

```
16522tabfavorites://
16524tabhttps://example.com/
```

탭 문자(`\t`)가 아니라 문자열 `tab`이 들어간다. 그 결과 파싱이 전부 실패해 창 목록이 항상 비었고, "새 창이 나타나지 않았습니다"라는 엉뚱한 사유로 실패했다. 창은 정상적으로 만들어져 있었다.

구분자를 `tell` 블록 밖에서 `character id 9`로 만들어 해결했다. 같은 이유로 줄 구분자도 밖에서 만든다.

이 종류의 오류는 코드만 봐서는 보이지 않는다. 생성된 스크립트도 문법적으로 멀쩡하고, 실행도 성공하며, 결과 문자열만 조용히 틀린다.

### 2. 브라우저 항목에 멱등 판정이 빠져 있었다

탭이 하나도 추가되지 않은 경우에도 창을 매번 다시 배치했다. 앱 항목은 `isSatisfied`로 현재 상태를 확인하는데 브라우저 항목에는 그 단계가 없었다.

결과 표에도 드러났다. 2회차가 `alreadySatisfied`가 아니라 `placed`로 나오면서 note가 비어 있었고, 아무것도 안 했다는 사실이 보고서에 남지 않았다.

탭 추가가 0건이고 창이 이미 목표 위치이면 `alreadySatisfied`로 보고하도록 고쳤다.

## 검증 중 겪은 환경 문제

첫 실행이 `unreachable`로 실패했다. Safari의 창이 다른 Space에 있어 AX가 조회하지 못했기 때문이다. 3단계까지의 검증이 남긴 상태였다.

보고 자체는 정확했다. `CGWindowList`로는 창이 2개 보이는데 AX는 0개라는 것을 구분해 "창 2개가 다른 Space에 있어 접근할 수 없습니다"로 알려줬다. 3단계에서 이 구분을 넣어둔 것이 여기서 값을 했다.

Safari를 종료해 현재 Space에서 다시 뜨게 하고 검증을 이어갔다.

이는 제품의 실제 한계이기도 하다. 사용자가 여러 Space를 쓰면 다른 Space의 창은 조회조차 되지 않는다. Space 지정과 함께 후속 사이클에서 다룬다.

## 알려진 한계

- 탭 순서는 첫 실행에만 정확하다. 이후 추가되는 탭은 창 끝에 붙는다. 순서를 보장하려면 기존 탭을 닫아야 하는데 사용자 작업을 지우게 되므로 택하지 않았다.
- 첫 URL이 같은 워크스페이스가 둘이면 `separate` 모드에서 서로의 창을 자기 것으로 착각한다.
- Chrome 경로는 생성되는 스크립트 문자열 단위 테스트로만 덮었다. 실제 실행은 검증하지 못했다.
- Apple Events 권한 거부(-1743) 경로는 이 머신에서 권한이 이미 승인되어 있어 재현하지 못했다. 코드 리뷰로만 확인했다.
